# Doctor repair: preserve existing item state

## Reproduced defect

Refreshing an eligible translated item's charge lore previously called the normal Rechargeable setter on the live item. That setter rounds charge to two decimal places. In a real project regression using the historical Bukkit object-stream encoding, Doctor therefore changed a saved FLOAT charge of `123.4567` to `123.46` while repairing presentation. Addon-provided state-reading or restoration callbacks also received the live item, so a defective callback could change its identity or amount even during inspection or before throwing.

The negative control in [run 36756298646](https://github.com/wickidcow/Slimefun-Legacy/actions/runs/36756298646) ran the original Doctor and failed specifically at the exact float-bit comparison: expected `1123477973`, actual `1123478405`. It was not a compilation, setup or unrelated failure.

## Correction and unchanged gameplay

Dynamic presentation capture and restoration now run on an isolated item clone. A clone that returns the original instance is rejected. A restoration hook that changes item ID, material or amount is refused instead of being committed to the live item. A failed callback leaves the original live amount and metadata untouched.

The result starts from the original ItemMeta and receives the repaired display name/lore. Existing typed persistent values are not overwritten. The existing legacy-lore recovery path can still add previously missing dynamic markers; this compatibility behavior is retained rather than stripping markers required by older items. A recovered missing charge marker receives the exact captured float, not the rounded display value. Display precision and the stored charge are separate.

Original PDC values, backpack/owner identity, stack amount, damage, enchantments, flags and custom-model components remain protected. Normal `ChargeUtils` and `Rechargeable` charging/gameplay implementations are unchanged. No item registration, research, recipe, table schema, serializer output, migration default or resource-pack mapping is changed. This is not an automatic item-template replacement or general authorization to migrate an unknown addon.

The existing orphan-name configuration remains honored. Unknown addon lore/identity is not guessed by this correction. Already-English items are not rebuilt. Dedicated resource-pack cleanup, provider-specific fingerprinted migrations and incomplete-inventory recovery remain separate operations; see [the owner workflow](doctor-inventory-recovery.md).
