- [ ] **Candidate source invariants:** `scripts/verify_legacy.py`, repository version/contract matrices and Java-bytecode target agree on `4.1.72`. Preserve the minimum supported Minecraft **1.21.11** and protected item/storage IDs.
- [ ] **Compatibility and regression:** real Paper/Purpur 1.21.11/26.2 tests; Paper 26.3; Purpur 26.3 experimental; required addon/API baseline comparisons against the **published 4.1.71 source**; Doctor read-only recovery, gameplay, proxy, migration/database fixtures. Report genuine skips.

- [ ] **Double-boot full stack:** Paper 1.21.11, 26.2 and 26.3 plus Purpur 26.3 build 2646. Require no addon linkage/enable/configuration-load failures, WorldEdit provider evidence, clean restarts and exact source provenance. Folia 26.3 remains outside the supported release gates.
- [ ] **Reproducible release:** two clean byte-identical core JAR builds against the exact candidate commit, `verify_release_artifact.py`, pinned resource-pack metadata/file hash and exact-source addon ZIP.
- [ ] **Publication:** only after reviewing every required gate, use **Reproducible Release** `workflow_dispatch` on the immutable final `master` commit. Publish three assets under the unused **v4.1.72** tag; verify actual release files and keep older tags/assets unchanged.
- [ ] **Live AlbionMC upgrade readiness (separate):** independently test the entire AlbionMC plugin set and a backed-up world copy. CI alone is not production-world approval.

## Preservation boundaries

The historical catalog and `/sf doctor migrations recovery` are identification-only; they never authorize generic repairs. Legacy `SHULKER_HELMET` registration was restored in 4.1.71; other EnderPanda IDs are not automatically rebuilt. Lucky Armor/weapon display names remain an explicit `/luckyrestore` opt-in in SF_LuckyBlocks 1.0.4.

No unrequested world conversion, live-server deployment, automatic addon migration, resource-pack activation or destructive storage repair belongs in this candidate. Minecraft 26.3 worlds may not safely downgrade; test on a clone and take backups before any server-version upgrade.

All versioned source and bundle evidence must be tied to the **actual final commit**. Historical PR CI and previous version release assets cannot be relabeled as final-source verification.
