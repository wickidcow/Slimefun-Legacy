## Separate startup storage investigation

Status: **unresolved, under process/file-operation trace**. The diagnostic used the published v4.1.71 core at `f68544e47d8489704d0e9d34adc65f0114b07153`, Paper 1.21.11 build 132 and three metadata-only fixture blocks in a disposable world. Seven ordinary delayed writes were still pending when the probe requested immediate orderly shutdown on the same owner thread. The preserved completed run has manifest SHA-256 `6bcdd96823ad803c9aeb746e5f5d47504a6ac5bdb3c1a53dfb7cd99b04892ef7`; its independent evidence is recorded in [PR #363](https://github.com/wickidcow/Slimefun-Legacy/pull/363).

| Captured boundary | Observed state |
| --- | --- |
| After the first normal shutdown | Intended final state: 3 records, 13 values; WAL/SHM absent |
| Immediately before restart | Identical main database and intended final state; WAL/SHM absent |
| Restart ready, before probe reads | Unchanged main database plus a newly observed WAL/SHM; the WAL view contains the older seed state: 2 records, 10 values |
| After the second normal shutdown | The older seed state is checkpointed into the main database; WAL/SHM absent |

The first shutdown persisted the intended metadata. The change is bounded to startup before the probe's reads. The actor introducing the WAL state and a reappearing clean-shutdown marker remains unknown; source inspection alone did not establish a restore mechanism. Both server processes stopped normally. This result does not establish a cause in Slimefun storage, the GitHub service, or Purpur, and it does not certify inventories, crash recovery or existing player worlds. Preserve the original failed diagnostic and record any traced rerun independently. Do not infer a storage pass from unrelated CI or implement a speculative save-order change.

## Preservation boundaries

The historical catalog and `/sf doctor migrations recovery` are identification-only; they never authorize generic repairs. Legacy `SHULKER_HELMET` registration was restored in 4.1.71; other EnderPanda IDs are not automatically rebuilt. Lucky Armor/weapon display names remain an explicit `/luckyrestore` opt-in in SF_LuckyBlocks 1.0.4.

No unrequested world conversion, live-server deployment, automatic addon migration, resource-pack activation or destructive storage repair belongs in this candidate. Minecraft 26.3 worlds may not safely downgrade; test on a clone and take backups before any server-version upgrade.

All versioned source and bundle evidence must be tied to the **actual final commit**. Historical PR CI and previous version release assets cannot be relabeled as final-source verification.
