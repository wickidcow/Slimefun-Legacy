# Slimefun Legacy 4.1.63

This release candidate combines the unreleased 4.1.62 compatibility work with the coordinated existing-item and addon-preservation fixes. The previous published stable baseline remains 4.1.61. Do not treat a candidate version or a passing compile as permission to skip backups and staging-server verification.

## Existing items and storage

Preserve item and research IDs, typed persistent keys, owner and backpack identities, machine contents and old item readers. Incomplete inventory reads must not be saved as empty inventories. Stage complete item serialization before database writes and retain recovery guards on failed loads or migrations. Item Doctor presentation repair keeps existing charge and custom metadata rather than rebuilding player items from current templates. New addon-created profiles retain a supplied machine-player name during their initial database write.

These changes do not globally convert world data, replace the native item writer, enable an optional migration, change ordinary recipes, production speeds, energy costs or transfer priorities. United-to-Legacy upgrades remain relevant; direct reverse compatibility with every United reader is not promised.

## Guide and maintained addon bundle

Retain the current master's child-folder visibility fix alongside the complete preservation branch. Guide recipe browsing, ownership, first-join delivery and cheat-click behavior retain their existing compatibility checks.

Rebuild all 45 maintained addon JARs from the exact source manifest against this release core. The aggregate SF_Addons_1.21.11-26.3.zip contains installable JARs plus source/hash records, not placeholder plugins. The final manifest and test ledger identify each selected source; any further verified addon refresh is recorded before publication.

The included preservation work covers Networks storage lookup and transfer behavior; InfinityExpansion2 metadata conversion; Supreme and FinalTECH item/configuration boundaries; SlimeEasy native-floor and profile compatibility; saved progression/preferences in Cultivation, CrystamaeHistoria, Galactifun, SlimeHUD and Advancements; FNAmplifications gem operations; LiteXpansion configurator data; and MagicExpansion complete payment, page selection, strict shop-file saves and identity-bound editor/chat actions.

## Runtime and release validation

Minecraft 1.21.11 is the runtime floor, not an age limit for saved data. Build with Java 25 and retain Java 21 plugin bytecode. Paper/Purpur are primary; Folia and other derivative-server gameplay and addon region safety remain qualified rather than universally certified. Record the actual build channel for 26.3 runtime tests instead of calling a beta server stable.

Runtime downloads use bounded retries and temporary files without switching build identities or weakening existing metadata/hash checks. The retained historical-item fixture can write real 1.20.6-era item encodings and world items, then check unchanged identities and typed data after supported-server upgrades, restart and explicit automatic-Doctor tests on disposable copies.

Require the new version's own full core tests, public API checks, canonical 45-addon build, provider-complete restart checks and reproducible-release workflow. Historical tests and mock fixtures remain individually attributed. They do not certify every captured customer world, populated machine, cross-region interaction, crash scenario or future upstream API.

## Upgrade procedure

Stop the server cleanly and back up the entire world and plugin data, including the Slimefun database and addon directories. Test the matching new core and intended addon JARs on a disposable copy first. Replace each existing plugin JAR rather than leaving duplicate old/new copies, and do not install unwanted addons merely because they are in the aggregate ZIP. Keep the same item/addon registrations and migration settings unless deliberately changing them.

Inspect startup diagnostics and /sf doctor storage recovery before running any optional repair or conversion. An unavailable or unreadable record is a recovery task, not an empty inventory to overwrite. Plugin rollback does not guarantee Minecraft world-version downgrade compatibility.
