# Slimefun Legacy 4.1.54

Slimefun Legacy 4.1.54 is a stability-focused release that finishes the move back to the standalone enhanced guide while tightening backpack persistence, Cargo transfer safety, and storage diagnostics.

## Standalone SF_JustEnoughGuide

- The preferred enhanced guide is the standalone **SF_JustEnoughGuide** addon.
- The former native Enhanced Guide remains available only as an opt-in compatibility fallback.
- When `JustEnoughGuide` is installed, Slimefun Legacy leaves the classic guide registered so the addon can replace it cleanly.
- Existing `plugins/Slimefun/enhanced-guide.yml` settings and `guide-bookmarks.yml` data can be imported by the maintained JEG fork.
- The required compatibility target is **SF_JustEnoughGuide 2.1.61**.
- The strict source pin used by required-addon CI was refreshed to the current 2.1.61 source commit instead of weakening or bypassing the compatibility gate.

## Safe guide registration API

Slimefun Legacy exposes supported guide registration methods so guide addons no longer need to overwrite the private guide registry through reflection:

- `registerSlimefunGuide(...)`
- `compareAndSetSlimefunGuide(...)`

The compare-and-set restore path prevents an addon from overwriting another guide implementation that replaced it later.

## Backpack persistence hardening

- Addon/API-opened `PlayerBackpack` inventories now use a detached persistence path when they were not opened through Slimefun's tracked backpack session.
- Detached saves no longer occupy or release the player's tracked backpack reservation.
- A completed detached save therefore cannot release a newer normal backpack session that the same player opened while the save was still running.
- Existing per-backpack async save ordering, immutable snapshots, partial-write recovery, and shutdown barriers remain intact.
- The storage correctness verifier now guards this session separation.

## Cargo transfer hardening

- Cargo re-resolves vanilla inventories after `CargoInsertEvent` and `CargoWithdrawEvent` before mutating their contents.
- Slimefun/custom menus are re-resolved after those events as well.
- If another plugin breaks, replaces, or invalidates the target during an event callback, Cargo no longer continues against the stale pre-event inventory object.
- This closes an item-loss/duplication window while preserving existing rollback, overflow, filter, and transfer behavior.
- Cargo correctness verification now explicitly guards live inventory revalidation.

## Doctor persistence diagnostics

`/sf doctor` now exposes backpack persistence state alongside the existing storage health information:

- active backpack save chains;
- uncertain backpack persistence baselines after failed or partial writes.

The public-safe Doctor support report also raises an attention warning when uncertain baselines exist. This is observational only: Slimefun retains the affected canonical cache to protect data and does not perform destructive automatic repair.

## Machine recipe and input-fill services

The Legacy machine recipe provider registry and hardened machine input-fill service initialize independently from the former native Enhanced Guide UI.

This keeps the following protections available to standalone guide addons:

- protection and target validation;
- region-thread ownership checks;
- transactional inventory planning;
- rollback on failed commits;
- registered addon machine adapters;
- alternative ingredient validation;
- maximum safe fill support.

## Compatibility and validation

The maintained compatibility range remains:

- Minecraft 1.21.11
- Minecraft 26.1.x
- Minecraft 26.2
- Minecraft 26.3

Paper and Purpur remain the primary targets, with Folia and Leaf as secondary compatibility targets.

Release validation includes the main Slimefun Legacy build, runtime gameplay correctness, public API compatibility, required-addon runtime checks, Paper 26.2 runtime smoke, Paper/Purpur 1.21.11 compatibility, Purpur/Folia/Leaf 26.2 smoke, and the Paper 26.2/26.3 full-stack smoke. The dedicated Paper 26.3 pre-release lane remains advisory.
