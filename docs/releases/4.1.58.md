# Slimefun Legacy 4.1.58

Slimefun Legacy 4.1.58 expands the Guide's Slimefun Doctor into a broader operations dashboard while keeping repair and migration safety boundaries intact.

## Slimefun Operations Center

The new **Slimefun Operations Center** gives administrators six live health lanes from one Guide screen:

- Items
- Storage
- Machines
- Addons
- Proxy
- Resource Pack

It also links directly to Performance Health, Upgrade Center, Storage & Persistence, Proxy & Player Identity, Resource-Pack Ownership, planned restart readiness and the existing Doctor Support Summary.

The dashboard is read-mostly. It routes into existing Doctor and ticker services instead of creating a second repair engine.

## Explicit resource-pack ownership

`configSFLAddons.yml` moves to config schema version 2 and adds:

```yaml
resource-pack:
  ownership-mode: auto
```

Supported modes:

- `auto` — backwards-compatible behavior based on the Legacy sender flag.
- `legacy` — Slimefun Legacy owns delivery of the configured official/custom ZIP.
- `external` — ItemsAdder, Oraxen, a proxy/server pack, or another system owns delivery.
- `none` — no Slimefun-textured pack is intentionally in use.

Ownership controls delivery only. It never rewrites `item-models.yml` or stored ItemStacks.

**EXTERNAL explicitly supports Legacy sender OFF + matching Slimefun model mappings ON.**

`NONE` may cause Doctor to recommend reviewing exact bundled mappings that are still active, but cleanup remains a separate confirmed action and is never automatic.

The v1 → v2 config migration inserts the ownership comments and `ownership-mode: auto` text-preservingly before normal default persistence so existing server-owner comments are not unnecessarily rewritten.

## Performance Health

Performance Health ties the GUI to the existing `/sf tick` runtime tools:

- ticker status
- live `/sf tick top` profiler sample
- targeted machine inspection
- paused ticker listing
- machine failure detail
- integration runtime health

Global ticker freeze/resume remains behind a confirmation screen and does not rewrite machine storage.

## Upgrade Center

Upgrade Center brings the existing guarded upgrade lanes into one read-only screen:

- legacy item IDs
- same-ID addon schemas
- exact placed-machine providers
- persisted block/universal IDs
- stored item payload formats
- persisted machine Slimefun Item IDs
- persisted backpack Slimefun Item IDs

The GUI deliberately does not execute migration fingerprints. Operators still use the exact short-lived command printed by the native scan for any mutation.

## Storage & Persistence

The Storage & Persistence Center shows:

- storage backend readiness
- pending database writes
- backpack save chains
- uncertain backpack baselines
- previous clean shutdown
- active Doctor work
- planned restart readiness
- normal-shutdown backup readiness

The existing `/sf doctor storage` two-pass/fingerprint workflow remains authoritative for integrity repair.

4.1.58 also fixes two issues in the existing SQLite shutdown backup service: the backup directory is now created when needed, and retention correctly recognizes timestamped `.zip` files and trims old backups beyond the 20-file ceiling.

There is intentionally no live **Force Backup** button.

## Proxy & Player Identity

Proxy Health surfaces the existing forwarding diagnostics and adds an online-player picker for `/sf doctor proxy player <name>`, making it easier to compare Bukkit UUID identity with the Slimefun profile owner and distinguish proxy-forwarding problems from actual persistence loss.

## Support reporting and safety

`/sf doctor report` now includes pack ownership, effective/raw sender state, backup readiness and proxy-forwarding evidence.

Regression gates protect:

- `EXTERNAL` combined-pack semantics
- `NONE` remaining review-only for model cleanup
- no automatic item-model removal
- comment-preserving config schema v2 migration
- migration execution staying behind native fingerprint gates
- shutdown backup directory creation and retention behavior

## Compatibility

The maintained compatibility range and runtime policy remain unchanged. Paper 26.2 is the primary production line, Paper/Purpur 1.21.11 remain supported compatibility-floor targets, and Paper 26.3 remains under dedicated candidate/full-stack validation.

4.1.58 uses exact released 4.1.57 commit `774317a5fe52cee8f74fb37278c945f5ce5bbb3f` as its release-blocking previous-stable baseline.

The canonical release publishes `Slimefun-Legacy4.1.58.jar` and the validated `SF_Addons_1.21.11-26.3.zip` bundle.
