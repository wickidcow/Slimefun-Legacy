# Slimefun Legacy 4.1.61

Slimefun Legacy 4.1.61 is a focused **Performance & Hot-Path Efficiency** release. The goal is to lower machine/network tick cost on large production servers without changing normal Slimefun gameplay timing, recipe precedence, EnergyNet distribution order, Networks routing order, or stored-world identities.

## Core machine and EnergyNet performance

- Energy Regulators reuse charge values already validated earlier in the same transaction instead of re-reading and rewriting unchanged capacitor/generator charge.
- Remainder storage skips no-op `setCharge` calls when the stored value is already correct.
- Healthy EnergyNet ticks no longer allocate a failed-generator `HashSet`; that structure is created only when a generator actually fails or explodes.
- `AContainer#findNextRecipe` now uses fixed slot arrays instead of per-scan `HashMap`/boxing work, snapshots input slots once, and checks material type before the full Slimefun item-similarity path.
- Electric Smeltery item-aware cargo routing now uses primitive six-slot buffers instead of `LinkedList<Integer>` + comparator sorting. Matching partial stacks are still preferred, smallest partial stacks still come first, and empty slots remain the fallback.
- InfinityExpansion2 Void Smeltery inherits the Electric Smeltery routing optimization without an IE2 gameplay change.

## Maintained addon hot paths

The canonical addon bundle is built from exact source revisions and includes the maintained performance work available at the 4.1.61 release source.

- **Networks:** stable NetworkRoot reuse for unchanged controller topology, transport-miss fast paths before expensive destination scans, reduced Auto Crafter idle/cache allocation churn, and lower pusher/line-transfer request/template allocation.
- **Supreme:** unchanged idle inputs no longer trigger repeated large recipe scans on GenericMachine-based Magical/Core fabricators; an input change wakes matching immediately and periodic revalidation remains in place.

## Compatibility evidence

- Addon comparison now **always tests the candidate core**, even if the current addon source no longer compiles against the previous stable Legacy baseline.
- A baseline-only failure is non-blocking only after the candidate source build succeeds.
- If both baseline and candidate builds fail, compatibility remains unproven and the required-addon gate fails closed.
- The previous-stable regression baseline advances to exact Slimefun Legacy 4.1.60 source commit `09f16ab0325b15153e5c84299d2bc9223810ff96`.
- Required addon runtime smoke, public API compatibility, Paper 1.21.11 compatibility, Paper/Purpur/Folia/Leaf 26.2 smoke, Velocity proxy smoke, and Paper 26.3 preflight remain release gates/evidence.

## Platform status

- **Primary production line:** Paper 26.2 / Java 25.
- **Legacy supported line:** Paper/Purpur 1.21.11 / Java 21.
- **Paper 26.3:** candidate/pre-release validation line; not promoted to the production baseline by this release.
- No Slimefun item IDs, research IDs, storage keys, database schema, saved-world format, or intentional normal gameplay semantics are changed by 4.1.61.
