# Slimefun Legacy 4.1.61

Slimefun Legacy 4.1.61 combines **Performance & Hot-Path Efficiency**, **JEG/Guide cleanup**, and **maintained-addon deprecation/build modernization**. The goal is to lower machine/network tick cost and clean up guide/addon integration without changing normal Slimefun gameplay timing, recipe precedence, EnergyNet distribution order, Networks routing order, or stored-world identities.

## Core machine and EnergyNet performance

- Energy Regulators reuse same-tick source charge/container snapshots instead of resolving and rewriting the same source state twice.
- Remainder storage skips no-op charge writes when the stored value is already correct.
- Healthy EnergyNet ticks allocate generator-failure tracking only when a generator actually fails or explodes.
- Regulator profiling no longer allocates an `AtomicLong` holder for sampled generator timing.
- Vanilla player-head power-state presentation reuses cached state objects instead of replacing a `CachedState` and cloned `Location` on every periodic validation.
- Unchanged regulator hologram states are skipped between periodic self-heal refreshes, avoiding repeated label formatting, location/block lookup, scheduler ownership checks, and hologram-service traversal.
- `AContainer` reuses the already-resolved `SlimefunBlockData` menu/location during normal ticker execution.
- `AContainer#findNextRecipe` uses reusable per-thread slot scratch buffers, snapshots input slots once, performs first-input/material rejection before exact Slimefun comparison, and keeps the established one-recipe-input-per-physical-slot semantics.
- Electric Smeltery item-aware cargo routing uses primitive six-slot buffers instead of boxed lists/sorting. Matching partial stacks are still preferred, smallest partial stacks still come first, and empty slots remain the fallback.
- InfinityExpansion2 Void Smeltery inherits the core `ElectricSmeltery` and `AContainer` improvements without an IE2 gameplay change.

## JEG / guide integration cleanup — issue #264

- Released **SF_JustEnoughGuide 2.1.67** with the correctly centered 3x3 recipe grid restored.
- Removed the duplicate machine-recipe slot that was occupying the recipe grid and shifting ingredients to the right.
- JEG no longer duplicates Slimefun's first-join guide delivery; Slimefun remains the single owner of `guide.receive-on-first-join`.
- Slimefun Legacy's existing lazy, TPS-budgeted **Recipes Using This Item** browser is exposed to the currently registered guide implementation so standalone JEG can use the same reverse-recipe index instead of maintaining a second one.
- JEG continues to install and restore its guide through Slimefun Legacy's supported public `registerSlimefunGuide` / `compareAndSetSlimefunGuide` ownership API.
- Exact broken maintained JEG layouts are migrated automatically while owner-customized layouts are left untouched.
- This issue is treated as a JEG/Legacy guide integration regression. **No InfinityExpansion2 changes are required for issue #264.**

## Maintained addon hot paths

The canonical addon bundle is built from exact run-resolved source revisions and includes the maintained performance work available at the 4.1.61 release source.

- **Networks 1.0.33:** stable `NetworkRoot` reuse for unchanged controller topology; limiter checks before expensive line-transfer discovery; canonical Location reuse in ticker/cache paths; direct topology traversal instead of temporary `BlockMenu` sets; lazy miss-list allocation; reduced access-history key cloning; Auto Crafter idle/cache cleanup; and reuse of preflight `ItemRequest` objects for withdrawal.
- **Supreme 1.0.16:** unchanged idle GenericMachine inputs use the established short idle backoff instead of repeated fingerprint/recipe work; idle fingerprint/deadline state is consolidated; recipe template/amount arrays are precomputed for transport matching; active reservation, rollback, persistence, energy, and recipe ordering remain unchanged.
- **MilitaryArsenal 1.1.8:** maintained-addon candidate builds no longer depend on deprecated Slimefun ticker, Bukkit metadata/title/color, or static enchantment-registry APIs. This removes a strict `-Werror` bundle blocker without changing turret or machine behavior.

## Maintained addon deprecation and build modernization

- **MilitaryArsenal 1.1.8** removes deprecated Slimefun ticker, Bukkit metadata, inventory-title/color, and static registry APIs while preserving turret/machine behavior.
- **AlchimiaVitae 1.0.4** remains part of the maintained modernized addon line and passes the current candidate bundle checks.
- **MobDrops 1.0.4** isolates javac in a forked compiler process for reliable Java 25 / Paper 26.3 candidate compilation while preserving the Java 21 universal runtime target and existing drop behavior.
- **SlimefunAdvancements 1.0.7** isolates javac for the Java 25/Paper 26.3 candidate lane and removes its hard build-time JEG dependency. JEG search-history support remains optional at runtime through a reflection bridge with the classic GuideHistory fallback preserved.
- The maintained addon bundle remains release-blocking: candidate sources must compile against the exact Slimefun Legacy candidate and strict deprecation/removal checks before packaging.

- The previous-stable regression baseline advances to exact Slimefun Legacy 4.1.60 source commit `09f16ab0325b15153e5c84299d2bc9223810ff96`.
- Required addon runtime smoke, public API compatibility, Paper/Purpur 1.21.11 compatibility, Paper/Purpur/Folia/Leaf 26.2 smoke, Velocity proxy smoke, Paper 26.2/26.3 full-stack smoke, and Paper 26.3 maintained-addon preflight remain release evidence.
