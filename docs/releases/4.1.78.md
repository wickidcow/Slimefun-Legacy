## Slimefun core improvements since 4.1.77

- **Safer Cargo and machine output accounting.** Validate explicit physical slots before preflight or insertion (#441); count repeated slots once (#447–#448); allow a recipe output to span several compatible partial stacks (#450); and safely ignore null/AIR/zero-count optional outputs without ever accepting negative-size results (#452, #460).
- **Respect inventory rules on both checks and commits.** Multi-output and actual insertion reject vanilla items forbidden by a destination inventory type, including nested shulker boxes (#453–#454). This also holds when other selected slots contain virtual Slimefun items (#456), and applies to the separate legacy Cargo/menu path (#466).
- **Do not lose or duplicate inventory items.** A merged vanilla stack is explicitly committed even if a Bukkit inventory returns a detached ItemStack copy (#459). Legacy Cargo does the same for successful pushes (#462) and item consumption (#463), with exact remainders, unchanged source inputs and persistence tracking.
- **Reject malformed or no-op mutations.** Legacy menus fail closed on nonpositive consumption, empty or invalid slots (#457), on malformed Cargo pushes (#461), and avoid rewriting cloned inventories when no items moved (#455). Virtual item consumption no longer increments the dirty-change sequence twice (#464).
- **Keep provided inventory backing intact.** An externally supplied BlockMenu inventory is not replaced with a new generic chest on the first lazy slot lookup (#468). Regression tests include real shulker backing and specialized small inventories.
- **Dependency and baseline reliability.** Isolate Paper API and pinned dependencies from unrelated Maven repository failures (#440), including rebuilds of the previous published baseline (#458).
- **More accurate profiler labels.** `/sf tick top` now distinguishes accumulated Slimefun ticker work and the configured ticker interval, without implying those results measure server-wide MSPT or TPS (#465). Measured ticker behavior and the original grade calculations are unchanged.

These repairs preserve existing Slimefun item IDs, machine recipes, Energy/Cargo routing contracts and persistent storage formats. Operator backups and matched-world testing remain essential.

## Coordinated r153 addon bundle — 44 maintained Java addons

The candidate `SF_Addons_1.21.11-26.3.zip` uses an **exact-source revision 153** manifest with 44 maintained addons. The operator removed BuildingStaff from the distributable roster; optional compatibility work for its original upstream plugin remains separate. The candidate selections include:

- **Networks 1.0.62:** explicitly persist accepted existing-stack merges (including detached reads), avoid extra menu-dirty updates scan specified-quantity line-transfer inventory capacity once rather than twice, and stagger interval-based line-transfer start phases to reduce dense-base bursts. Preserve storage databases, blueprint recipes, item conservation, rollback receipts and ticker schedules. Prior live profiling showed 400 autocrafter samples accounting for 32.31 ms of aggregate callback work; this is **not** a claim of improved TPS or MSPT.
- **HotbarPets 1.0.4:** introduce optional per-pet ability permissions, with `permission-gating.enabled: false` by default. Albion operators may opt in using `albion.hotbarpet.*` nodes (for example `albion.hotbarpet.cow`) without restricting crafting, trading or possession. A permission is rechecked before delayed Pig and Zombie effects. Favorite pet food must remain in the player's inventory for effects that consume food.
- **InfinityExpansion2 2.0.16:** promote tested Mob Data Card appearance and on-interaction refresh logic, preserving item quantities, typed PDC, custom model metadata, and the prior 2.0.15 network-storage ownership and recovery repairs. This does not sweep offline player inventories or unloaded chunks.

**MagicExpansion 1.1.19** includes reviewed Water Cloud fishing/guide parity and opt-in classic rod bonuses; **JustEnoughGuide 2.1.74** includes first-join and recipe-completion safety. **DankTech2 1.1.04** is pinned to the final merged Java-only WildStackerAPI 2026.3 update (source `410aff9e4dae5372a5ac148684ba5eeec01c0f48`); the v1.1.04 standalone release is checksum-verified; real WildStacker item-conservation testing remains an operator staging priority. SlimeHUD 2.0.7 and the other maintained selections remain pinned. The selected standalone updates are published, but this source manifest remains a release candidate until the exact native/storage and source-digest gates pass.

The names and versions above represent pinned source selections, not permission to bypass final exact-binary native runtime or reproducible release gates. Never replace a previously published release asset in place.

## Platforms and acceptance

- Minecraft 1.21.11+ with **Paper** as the primary platform and **Purpur** validation, including the 26.2 and 26.3 API targets.
- **Leaf** and **Folia** undergo their own runtime and restart smoke tests. Folia multi-region Cargo/Energy/storage transactions and all third-party addon gameplay are **not** automatically certified by a green startup check; InfinityExpansion2 does not declare full Folia support.
- The core JAR uses **Java 21 bytecode** built and tested under Java 25 where required by newer Paper APIs.
- Before an official publication: require **two byte-identical clean core builds**, dependency and public API/baseline comparisons against v4.1.77 (published baseline commit `a8b62908e6fb8fd949f585faa7de30e863c6deaa`), the exact 44-addon source/asset manifest, maintained-addon compile/test gates, Paper/Purpur full-stack multi-restart evidence, Leaf/Folia readiness, native storage/crafter/conservation/receipt tests and the exact release-source integrity checks.
- **No release until every required gate is green for the final source commit and addon pins.**

## Installation, rollback and optional assets

Stop the server, back up worlds, Slimefun block storage, Networks/InfinityExpansion2 databases and plugin configurations, replace the core and validated compatible addon JARs together, then restart normally. Do **not** use `/reload` for upgrades. Test existing storage and player-owned pets before removing backups.

Official assets remain the **core Java JAR**, the canonical verified **44-addon ZIP**, and the existing optional official **Java resource pack**, carried unchanged. Other optional drop-in resource-pack directories, when already present in packaging, are to be preserved unchanged; no new Bedrock/Geyser functionality or integration is part of this release.

Release 4.1.78 should be tagged and published only after the final reproducible-release workflow verifies all asset hashes. The previous public releases and their binaries must remain immutable.
