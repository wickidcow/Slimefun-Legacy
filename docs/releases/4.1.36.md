# Slimefun Legacy 4.1.36

Slimefun Legacy 4.1.36 adds a dedicated, release-only update notification service for server owners while preserving the stability and compatibility work from 4.1.35.

## Highlights

### GitHub Release-only update notifications

Slimefun Legacy can now tell a server owner when a newer **published GitHub Release** is available.

- The first release check runs asynchronously during server startup, so it does not block Slimefun or delay the main server thread.
- Long-running servers repeat the lightweight release check once per hour.
- Release discovery uses GitHub's `releases/latest` endpoint for `wickidcow/Slimefun-Legacy`.
- Drafts, Actions builds, branch commits, and ordinary development commits are not treated as updates.
- Both modern tags such as `v4.1.36` and older tags such as `SlimefunLegacy4.1.31` are understood by the version comparison logic.
- When a newer release exists, the console notice shows the installed version, latest release version, and the actual GitHub release page.
- Online operators can also receive the same release notice once per published tag.

### Notification only — no self-replacing JAR

The Legacy update service intentionally **does not automatically download or replace Slimefun**.

The older community/upstream auto-update path remains disabled even if an old server configuration has `options.auto-update: true`. If that setting is encountered, Slimefun Legacy explains that the option is ignored and that update discovery is handled through published GitHub Releases only.

This prevents an English Slimefun Legacy installation from being silently replaced with another fork or an unreviewed development build.

### Failure-safe startup behavior

A GitHub outage, API error, or network timeout cannot stop Slimefun from enabling. The release request runs off the main server thread and the rest of Slimefun continues normally whether or not GitHub responds.

The existing GitHub cache remains usable as a fallback, but update notices are only based on release information originally obtained from the GitHub Releases API.

### Release-gated behavior

A dedicated `verify_github_release_updater.py` invariant is now part of the full Slimefun Legacy verification suite. It protects the release-only endpoint, asynchronous startup behavior, version-tag parsing, console notice content, and the permanent disabling of the old community auto-updater.

## Compatibility

- **Paper 26.2 / Minecraft 26.2** — primary supported line, Java 25
- **Purpur based on Paper 26.2** — supported
- **Folia based on Paper 26.2** — experimental
- **Paper/Purpur 1.21.11** — supported compatibility line
- Slimefun-owned classes continue targeting **Java 21 bytecode**

No Slimefun item IDs, recipe IDs, machine storage formats, player data formats, or database schemas are changed by the update service.

## For server owners

4.1.36 is intended as a drop-in upgrade from 4.1.35. Replace the previous Slimefun Legacy JAR and perform a full server restart rather than `/reload`.

After this release, a server still running an older Slimefun Legacy version will receive a clear console notice during startup once GitHub reports 4.1.36 (or a later published release) as the newest release.
