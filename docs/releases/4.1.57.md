# Slimefun Legacy 4.1.57

Slimefun Legacy 4.1.57 turns the Guide's administrator Doctor page into a guided recovery console and makes custom/combined resource-pack setups an explicit supported workflow.

## Guided Doctor console

Operators with `slimefun.command.doctor` now get a live **Recommended Fix / Doctor Assistant** at the top of the Doctor console. The assistant reads existing Doctor, storage, machine, dependency, addon, integration, resource-pack and item-model diagnostics and routes the operator to the safest existing lane.

It is deliberately read-only: detecting a problem never triggers a server-wide repair, migration, machine retry or item-model rewrite automatically.

The console now includes:

- **Resource Pack Preflight**
- **Player & Item Repair**
- **Addon & Dependency Health**
- **Runtime Recovery**
- expanded **Other Doctor Fixes**
- **Doctor Support Summary**
- live counts and a one-click refresh

## Custom and combined resource packs

Legacy's resource-pack sender and Slimefun item-model mappings are now presented as two independent states.

Supported setups include:

1. **Slimefun Legacy sends the pack** — enable Legacy's sender and use either the official URL or your own hosted combined pack.
2. **ItemsAdder, Oraxen, a proxy or another system sends the combined pack** — leave Legacy's sender disabled while keeping matching Slimefun item-model mappings enabled.

Disabling Legacy's sender does **not** remove `item-models.yml` mappings or rewrite stored items.

Doctor also no longer treats the historical v4.1.52 migration marker as evidence that mappings should be removed. Historical mappings may be intentional when a custom pack still uses the Slimefun models.

## Resource Pack Preflight

The preflight screen shows:

- Legacy sender enabled/disabled state
- required/optional state
- configured URL validity
- SHA-1 validity
- known external pack-manager detection
- bundled mappings currently active
- bundled mappings still at zero
- custom/non-matching mappings preserved
- exact bundled removal candidates

**Test Configured Legacy Pack on Me** sends the configured pack only to the administrator without enabling global delivery, changing the saved player preference, or touching item-model mappings.

## Targeted repairs

The new Player & Item Repair screen supports:

- read-only held-item inspection
- confirmed held-item presentation repair
- read-only self inventory + ender-chest inspection
- confirmed self repair
- online-player picker for confirmed targeted inventory + ender-chest repair

These paths do not start the server-wide Doctor repair.

## Addon and runtime recovery

Addon & Dependency Health exposes compatibility evidence, missing/disabled hard dependencies, addon Doctor scans, registry health and the cross-fork addon API view.

Runtime Recovery exposes storage/runtime status, core health, chunk health, machine failure detail and external integration status. Targeted/all machine retries and integration reloads are available only behind confirmation screens and keep their existing no-storage-rewrite boundaries.

## Support reporting

The GUI Support Summary provides one compact view of platform, storage, machine, pack/model, dependency, addon, integration and last-Doctor state.

`/sf doctor report` now includes a dedicated **Resource Pack + Item Models** section and prints the existing Doctor next-step classification. The report explicitly notes that Legacy sender OFF with Slimefun mappings ON can be correct for a custom/combined pack.

## Safety invariants

4.1.57 adds verification that:

- Legacy sender disable never implies model cleanup
- custom/combined pack delivery remains a supported configuration
- model removal remains explicit and confirmed
- custom/non-matching model values remain protected
- the Doctor Assistant remains routing-only
- server-wide mutation remains behind the existing Doctor confirmation boundaries

## Compatibility

The maintained compatibility range remains Minecraft 1.21.11 through the 26.x line currently covered by Legacy CI. Paper 26.2 remains the production baseline, with Paper 26.3 candidate/full-stack validation retained. Velocity modern forwarding remains the maintained proxy path.

4.1.57 uses the exact released 4.1.56 source commit `dbb1657ef530ccbb532f8c665537de104355ecba` as its release-blocking previous-stable baseline.

The canonical release publishes the raw `Slimefun-Legacy4.1.57.jar` plus the validated `SF_Addons_1.21.11-26.3.zip` bundle.
