# Slimefun Legacy 4.1.80 — Item identity diagnostics and preservation

Status: unpublished candidate. Publication requires reviewed addon sources and fresh exact-source release evidence. The published v4.1.78 and v4.1.79 tags and assets remain immutable.

## Core changes since 4.1.79

- `/sf doctor identity compare` compares held items against each other and against their own registered templates, including typed PDC and modern model components. Inspection reads the original inputs without invoking item clone hooks. Unregistered templates are reported as unavailable.
- Configurable crafting restrictions can prevent crafting while keeping existing items available. Saved menus restore callbacks and inventory interactions. Electric Smeltery per-ingredient cargo caps are restored.
- Ticker and storage lookup optimizations reuse keys and resolved tickers while preserving the established machine processing order.

Historical inventories are not rewritten. This is not a blanket repair for older nonstacking items, and functional PDC, ownership and saved data remain significant.

## Actual identity evidence and limits

The native fixture now exercises ten narrow cases on connected Paper 26.2 build 129 and Folia 26.2 build 7: three actual give-command items; the copper-wire crafting handler; native wire-byte reload after process restart; ender-chest persistence; backpack database persistence and public API reload; coal-block-to-Carbon Compressor output; and actual Carbon consumed by the compressed-Carbon recipe. Negative controls cover incomplete and cancelled crafts without ingredient loss or delayed output leakage. Templates remain unchanged.

These are production handler calls in disposable fixtures, not network right-click or multiblock-discovery coverage. The other four native runtime lanes have zero actual producer cases. Registry accounting still marks all 627 items / 3762 broad producer combinations UNTESTED. Cargo, all recipes, all storage backends, old-world migration and every addon producer are not certified by these tests. Pre-bump CI receipts do not validate this release candidate.
