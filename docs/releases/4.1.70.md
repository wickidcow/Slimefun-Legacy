# Slimefun Legacy 4.1.70

## Coordinated core and addon stabilization

This release candidate assembles the current preservation-first Slimefun Legacy core with canonical addon bundle revision **125**, containing **45 maintained addon JARs**. It is a coordinated release candidate, not another isolated FinalTECH version increment. Publication remains conditional on the exact-source gates recorded in [the release readiness ledger](../release-candidates/4.1.70.md).

The addon source matrix remains frozen: all 45 source commits, public filenames, exclusions and compatibility policy are retained from merged PR #346. FinalTECH is pinned to the published **3.0.15** source, `6b22072b7977366aa8690b17523ece96f9fba085`. Key versions in this set include Networks **1.0.49**, InfinityExpansion **2.0.11**, Supreme **1.0.20**, JustEnoughGuide **2.1.71**, and MagicExpansion **1.1.9**. The generated `SF_ADDON_MANIFEST.json` and `SHA256SUMS.txt` inside the final ZIP are authoritative for the complete inventory.

FinalTECH 3.0.15 includes the previously validated bounded lock-waiter error recovery and lock-drain snapshot repair. It retains existing public/protected method descriptors, timeout and diagnostic policies, and saved-data formats. No additional FinalTECH development candidate is substituted into this release set.

## Compatibility baseline

The release-blocking previous-stable baseline advances to the core JAR actually delivered in the **4.1.69 post-release refresh**, source `d430eda74525b31328660bc3d3e36e13c9869353`. That refresh includes the Hologram Display Projector. The original `v4.1.69` tag identifies an earlier source and is deliberately not used in place of the delivered refresh.

The 4.1.15 historical source remains an advisory drift baseline. Existing saved items, inventories, backpacks and machine identities may be older than the supported server runtime and must not be discarded or rebuilt from guide templates during an upgrade.

Minecraft **1.21.11** remains the minimum runtime target; **26.3** is the primary API target with **26.2** compatibility retained. Plugin bytecode remains compatible with Java 21. The exact API and server versions exercised must be read from the release's recorded CI evidence: an API compile, especially against an alpha or release-candidate API, is not evidence that a stable server build was tested.

Paper and Purpur remain the primary platforms. Leaf/Folia coverage is specific to the plugin and scenario tested. A core smoke test or a metadata declaration is not certification of every addon on Folia; do not assume that every JAR in the archive can be installed there.

## Packaging and optional integrations

The intended coordinated release assets are:

- `Slimefun-Legacy4.1.70.jar`
- `SF_Addons_1.21.11-26.3.zip`, built and validated against the same final core source
- `SlimefunLegacyRP.zip`, copied from the existing hash-pinned stable official pack

The resource pack remains optional. No preview pack promotion, automatic texture migration, server configuration replacement or live-server change is part of this candidate.

The WorldEdit bridge is named `SF_SFWorldEdit1.0.6_(1.21.11-26.3).jar` and needs a compatible WorldEdit API provider, such as the supported WorldEdit or FAWE setup. The main bundle does not supply that external provider. Install only the addons and matching dependencies that the server intends to use.

`SF_BetterStructuresLink` is a separate optional bridge requiring BetterStructures. Its existing `0.3.1-SNAPSHOT` development artifact is not one of these 45 JARs and is not silently promoted or included by this release. Its stable version, genuine-API build and BetterStructures integration need separate validation. Rebar/Pylon optional-provider work remains outside this coordinated Slimefun release candidate.

Magic Legacy (`SF_Magic_RSC`) remains separately installed when wanted; MagicExpansion remains bundled. Integrated Magic8Ball, archived ExtraTools/WorldTaste and the superseded historical DracFun addon are not reintroduced as duplicate standalone plugins.

## Upgrade and verification boundaries

Stop the server before replacing plugin JARs. Back up the worlds, Slimefun data storage, addon data and configuration folders. Keep existing configuration and language files, and remove superseded duplicate JARs rather than leaving two versions of the same plugin installed.

Validate the complete selected plugin set on a copy of the server first. Include old custom items, existing and nested backpacks, machine inventories, Cargo and Networks transfers, guide/menu interactions, and a save/restart cycle. Compare item counts, identities and stored state before and after. Do not turn a diagnostic or unreadable-record report into permission to clear, quarantine, migrate or rewrite player data automatically.

The 4.1.70 preparation changes release metadata and documentation, not runtime Java code or addon source pins. The final release must pass fresh core/API/addon checks, exact-source full-stack tests and reproducible core packaging. The earlier revision-125 PR artifact contains a GitHub test-merge source identity and must not be relabeled as the final 4.1.70 bundle.

No claim of perfect behavior, unrestricted Folia support, universal old-world compatibility, or cross-fork rollback follows from successful compilation, archive checks, or startup tests alone.
