# Slimefun Legacy 4.1.64

Maintenance release following 4.1.63. Preserve the existing Slimefun content and saved-data identities while fixing cancelled block-removal persistence and aligning the tested addon bundle with current standalone releases.

## Storage correctness

When a block removal is cancelled, persist pending deletions as well as pending writes. Previously, removed settings could disappear from the live cache but return from the database after restart. The correction preserves empty-string values, clears stale values introduced by delayed loading, and uses the existing persistence scheduler. No new disk marker, schema conversion or automatic migration is introduced. This prevents future occurrences; it does not reconstruct deletions already lost before installation.

Item IDs, research IDs, persistent key names and types, inventories, backpacks, serialized item formats, recipes, machine rates, energy costs and transfer priorities remain unchanged. Historical item readers and conservative recovery behavior remain in place. Shared identities alone do not guarantee that a different fork can read every storage format.

## Maintained addons

The canonical source manifest advances to revision 102 with all 45 maintained addons retained. HotbarPets 1.0.3 and SimpleMaterialGenerators 1.0.5 are new independently published raw JAR releases; previous release assets remain untouched. Other revision 101 source selections remain unchanged.

HotbarPets uses the supported crafting-menu builder instead of the deprecated workbench-opening API, retaining its virtual 3x3 view, forced access and sound. Thirteen project tests protect current persistent markers and legacy entity-owner reads. SimpleMaterialGenerators adds eleven tests for exact production cadence, full-inventory retry, output metadata and progress cleanup; its production generator code is unchanged by that version update. Both addon release builds compare two clean packages byte-for-byte and exclude test libraries from their raw JARs.

Each addon also remains available as a standalone raw JAR in its own repository's Releases. The ZIP is the aggregate collection, not a requirement for downloading a single plugin. Install only the addons intended for the server and replace old JARs rather than leaving duplicate versions.

## Release validation

The published-bundle validator now checks the WorldEdit filename against the manifest's declared compatibility range instead of an obsolete 26.2 suffix. It validates the outer release-asset digest, exact JAR membership, per-JAR checksums, archive integrity and plugin descriptors without extracting or rewriting files. Twenty regression tests cover the naming and archive checks.

Validation evidence is attributed to exact source commits and artifacts in the accompanying maintenance checkpoint and test ledger. The pending-removal regression was reproduced using the original released code and verified through real database restarts. New pet/generator functional checks used identical addon JARs on Paper 1.21.11, 26.2 and 26.3; a connected-player workbench check was exercised on 26.2. These are scoped tests, not exhaustive populated-world, live-player, cross-region, crash-atomicity or server-TPS certification.

Publication requires this version's own complete core tests, supported-platform/API checks, canonical 45-addon build, provider-complete full-stack restarts and exact-master-source reproducible-release workflow. Do not use an earlier green source or a development test-merge artifact as a substitute for those checks.

## Compatibility and upgrade procedure

Minecraft 1.21.11 is the runtime floor, not an age limit for saved items. Paper 26.3 is the primary target, with 1.21.11 and 26.2 retained. Paper/Purpur are primary platforms; Leaf/Folia and addon region-safety claims remain qualified. Record whether a tested upstream server is beta or stable.

Stop the server cleanly. Back up the entire world, Slimefun database and all addon data. Test the matching core and intended addon JARs on a disposable copy before updating production. Keep existing item registrations and migration settings unless making an intentional change. Inspect startup diagnostics and `/sf doctor storage recovery` before running any optional repair or conversion. An unreadable record must not be treated as an empty inventory to overwrite. A plugin rollback does not guarantee Minecraft world-version downgrade compatibility.
