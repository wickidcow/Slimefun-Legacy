# Slimefun Legacy 4.1.64

This maintenance release builds on published 4.1.63. It retains the established Slimefun item and research IDs, typed persistent keys, storage identities, inventories, recipes, machine production rates and migration defaults. Minecraft 1.21.11 is the supported runtime floor, not an age limit for saved items or worlds.

## Core storage correction

When a block's pending removal is cancelled, pending deletions now reach the existing persistence scheduler as well as pending writes. Previously a deleted setting could disappear from the live cache yet remain in the database and return after restart. The private deletion marker exists only in memory; no new persisted marker or storage format is introduced. Empty strings remain real values. Permanently removed containers do not replay changes.

This fixes future cancellation handling; it cannot reconstruct deletions already lost before installation. It is not a redesign of cross-thread block removal or Folia region ownership.

## Legacy item colors

Retain the merged SlimefunItemStack color correction from PR299. Existing section-sign colors and Bungee-style RGB strings are preserved while valid ampersand codes are normalized before Adventure rendering. This restores the compatibility behavior used by MagicExpansion and other legacy addons without returning to the deprecated Bukkit color API. Item IDs, persistent keys, recipes and saved data formats do not change.

The canonical selection contains all 45 maintained addons from source-manifest revision 104. It retains the completed revision-103 storage and provider integrations and the newer SlimeTinker update:

- Networks 1.0.47: complete sort-mode cycling and immediate display-cache invalidation for changed filters/sort choices. Repeated equivalent choices and paging retain the cache. Storage contents, transfer priorities and quantum-storage category order are unchanged.
- BetterChests 1.0.3: conservative storage-adapter refusal, retained old item readers and exact Cargo mutation behavior, with loaded-only Doctor inspection.
- BuildingStaff 1.0.35: optional Rebar/Pylon placement and breaking using exact item payment, normal provider/protection events, and verified rollback before refunds. Providers remain optional and are not bundled. Their supported server versions are independent of the Slimefun floor.
- FluffyMachines 26.2.13: first-item barrel registration retained while either output buffer contains items, refusal of ambiguous saved state, private hover-label cleanup, and guarded item-frame interactions.
- SlimeTinker 2.0.7: permanent native name/lore rendering with preserved text, ordering and colors. Tool state, traits, progression, modifier costs, durability, IDs, typed keys and recipes are unchanged by that cleanup.

All source selections and exclusions are identical to the revision-104 matrix already merged in master. This release rebuilds the bundle against its own exact 4.1.64 source; it does not relabel the earlier 4.1.63-tested archive. The existing 4.1.63 release and its addon ZIP remain separate recovery references.

Individual addons retain standalone drop-in JARs in their own repositories. The aggregate ZIP is a convenience bundle containing plugin JARs and source/checksum records. Install only the addons intended for your server, and replace old copies rather than leaving duplicate JARs.

## Compatibility and validation scope

Paper 26.3 is the primary API/support target; runtime evidence records the actual server channel rather than assuming beta builds are stable. Paper/Purpur 26.2 and 1.21.11 remain backwards-compatibility lines. Core builds use Java 25 while retaining Java 21 plugin bytecode for the 1.21.11 floor. Leaf/Folia support and each addon's region safety remain qualified.

The previous-stable regression baseline is the exact published 4.1.63 source. Publication requires normal versioned core/API/platform checks, the exact-source canonical 45-addon rebuild, provider-complete restarts and the two-clean-build reproducible-release gate. Earlier addon or preparation runs are not substituted for this release's checks.

Focused core and addon fixtures include old-version data producers followed by upgrade and independent restarts. Separately attributed SlimeTinker tests cover generated-text rendering and actual native item rebuilds with owner separation, typed metadata and restart persistence. Those tests used the published 4.1.63 core; new 4.1.64 full-stack tests are separate. Generated fixtures, mock API boundaries and synthetic player interfaces do not certify every populated customer world, external-plugin interleaving, crash, cross-fork rollback or future API.

See docs/coordinated-addon-r104.md for the reconciliation checkpoint. The retained addon test ledger records individually attributed historical runs, not a single new all-45 gameplay test. Tests and server checks are not guarantees of all third-party behavior.

## Upgrade procedure

Stop the server cleanly. Back up the complete world, Slimefun database and addon data directories, then test the matching core and intended addon JARs on a disposable copy. Keep registrations and migration settings unchanged unless deliberately changing them. Inspect startup diagnostics and /sf doctor before attempting optional repairs or conversions.

Do not treat unreadable data as an empty inventory to replace. Restore or investigate the original record instead. Plugin rollback does not guarantee Minecraft world-version downgrade compatibility, and identical item IDs alone do not prove that every fork can read every serialized component.
