# Slimefun Legacy 4.1.81 — Doctor and coordinated addon updates

This version integrates the opt-in historical Doctor improvements and a coordinated 44-addon archive, including eight newer officially tagged addon versions. The reviewed source was merged by [PR #611](https://github.com/wickidcow/Slimefun-Legacy/pull/611). Publication is gated on exact final `master` source, two reproducible Java 21 core builds, the verified 44-addon ZIP, native/full-stack evidence and independently checked release assets. The previous [v4.1.80](https://github.com/wickidcow/Slimefun-Legacy/releases/tag/v4.1.80) release and its four assets remain immutable.

## Included core fixes

- **Historical Slimefun item diagnostics and explicit held-stack repair:** merged [Doctor PR #607](https://github.com/wickidcow/Slimefun-Legacy/pull/607) into master at `8c6b8ca16bfde539818f30f52880392b51759bb2`. Scan compares current registered identity to actual held items; only a precisely verified presentation-only candidate may use a fresh, private, owner-scoped original-byte backup and one-held-stack confirmation. Backup receipt verification and rollback work across clean restarts. Typed PDC, owner, item model, opaque components and quantities must match or the repair refuses.
- **No automatic historical rewrite:** Historical inventories are not rewritten. Old Fluffy Barrels, Cargo buffers, closed inventories, backpacks, machines, world records and offline players are **not** migrated or modified by the Doctor held-item command. The genuine historical AlbionMC `RAW_CARBONADO`/`CARBON_CHUNK` repair, 63+1 merge, recovery across two real-world boots is **UNTESTED** on owner-world originals and must be run on a backed-up clone before use; CI's synthetic native fixtures are not a universal old-world guarantee.
- **Infernal talisman provenance:** [merged #609](https://github.com/wickidcow/Slimefun-Legacy/pull/609) identifies InfernalExpansion-owned `PIGLIN_TALISMAN`/`ENDER_PIGLIN_TALISMAN` in read-only Doctor diagnostics; it does not invent missing items or register absent addons.
- **Crafting restrictions and compatibility:** existing `CraftingRestrictions.yml` administration, item identity diagnostics, old-item readers, machine/Cargo safety guards and support for the classic guide are regression targets, not automatic conversion features.

## Release provenance and safety

- [PR #611](https://github.com/wickidcow/Slimefun-Legacy/pull/611) merged the verified v4.1.81 source and eight addon revisions after 30 successful exact-PR-head workflows. The **published release** must be checked against its **actual final master commit**, not merely the GitHub PR merge-test commit.
- The release workflow requires two clean reproducible core builds with matching hashes, canonical 44-addon manifest/source and byte receipts, required native/full-stack test evidence, and the original separately verified Java and Geyser resource packs. Only a distinct immutable `v4.1.81` tag and four assets are permitted; no earlier tag or file may be overwritten.
- Doctor's held-item historical repair and IE2's old Chinese display-name presentation repair are disabled/opt-in and **not certified on genuine AlbionMC historical data**. Back up worlds, playerdata and plugin storage and validate two separate clean boots and exact rollback in a disposable server clone before invoking any repair. No automatic storage/cargo/world conversion, or blanket cross-fork historical rollback claim, is implied.
