# Slimefun Legacy 4.1.35

Slimefun Legacy 4.1.35 is a core stability and compatibility release. It keeps Paper 26.2 as the primary production target while extending the tested compatibility line back to Minecraft 1.21.11 for servers that have not moved to the 26.x version scheme yet.

## Highlights

### Paper and Purpur 1.21.11 compatibility

4.1.35 now carries explicit CI coverage for the older 1.21.11 server line:

- **Paper 1.21.11** — supported compatibility target on Java 21.
- **Purpur 1.21.11** — supported compatibility target on Java 21.
- Slimefun source is compiled against the **Paper 1.21.11 API** as a compatibility gate.
- The normal production 4.1.35 JAR is boot-tested twice on both Paper 1.21.11 and Purpur 1.21.11.
- Both runtime tests execute `/sf doctor upgrade`, require a clean shutdown, and verify the second boot recognizes the previous clean Slimefun shutdown.

**Paper 26.2 / Minecraft 26.2 on Java 25 remains the primary supported production line.** The 1.21.11 lane exists to preserve a validated compatibility option for servers that intentionally remain on that release.

### Core storage and chunk lifecycle improvements

4.1.35 reduces unnecessary retention of Bukkit world, chunk, and location objects in the storage runtime. Delayed writes and unloaded chunk caches now use safer immutable identity data and release normal block-storage caches only after pending reads, writes, inventories, and ticker state are safe to detach.

These changes are intended to reduce long-running memory retention while preserving existing database rows, storage keys, saved-world data, and normal Slimefun machine behavior.

### Safer scheduler and runtime behavior

Chunk-related work is routed through ownership-safe scheduling paths without resolving Bukkit blocks before scheduler handoff. This improves compatibility with modern Paper scheduling rules and continues the groundwork for experimental Folia support without changing normal Paper Cargo or Energy semantics.

### Startup and item-model reliability

Item-model defaults are loaded before immutable Slimefun item templates are created. This fixes startup finalization regressions that could interfere with normal PostSetup processing, Curios, Adventurer's Tools, Irradiated Arsenal, world settings, and item loading.

Paxel model handling and enchant compatibility were also refined so the newer Deepcore and Curios tools remain visually independent and behave more consistently with their underlying pickaxe/shovel tool roles.

## Compatibility

- **Paper 26.2 / Minecraft 26.2** — primary supported line, Java 25
- **Purpur based on Paper 26.2** — supported
- **Paper 1.21.11** — supported compatibility line, Java 21
- **Purpur 1.21.11** — supported compatibility line, Java 21
- **Folia based on Paper 26.2** — experimental
- Slimefun-owned classes continue targeting **Java 21 bytecode**

The 1.21.11 support claim is gated by both API compilation and real two-boot server runtime checks. Addons still need to support the Minecraft/Paper version they are being run on; core compatibility does not guarantee every historical addon build.

## For server owners

4.1.35 is intended as a drop-in upgrade for existing Slimefun Legacy installations. Back up your worlds, Slimefun data, databases, and addon data before changing core versions, and perform a full server restart rather than `/reload`.

This release continues the Slimefun Legacy goal of preserving the classic Slimefun experience and addon API while keeping the core usable across modern Paper-based servers.
