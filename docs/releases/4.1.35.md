# Slimefun Legacy 4.1.35

Slimefun Legacy 4.1.35 is a core stability and compatibility release. It keeps Paper 26.2 as the primary production target while extending the tested compatibility line back to Minecraft 1.21.11 for servers that have not moved to the 26.x version scheme yet.

## Highlights

### Wider Paper-family runtime validation

4.1.35 now carries real two-boot runtime smoke coverage across the main Paper-family targets:

- **Paper 26.2 / Java 25** — primary supported production line.
- **Purpur 26.2 / Java 25** — supported and two-boot runtime tested.
- **Folia 26.2 / Java 25** — two-boot runtime tested, but still **experimental** for gameplay and addon safety.
- **Paper 1.21.11 / Java 21** — supported compatibility target.
- **Purpur 1.21.11 / Java 21** — supported compatibility target.

Every runtime smoke starts the normal production 4.1.35 JAR twice, executes `/sf doctor upgrade`, requires a clean shutdown, and verifies that the second boot recognizes the previous clean Slimefun shutdown. The Paper/Purpur 1.21.11 lane also executes `/sf versions` on both boots so command-level Adventure/API linkage is validated in addition to startup.

Folia remains experimental even though its runtime smoke passes. A successful clean boot proves that the core can load, run its startup diagnostics, shut down, and restart on Folia; it does not guarantee that every Slimefun machine, cross-region interaction, or third-party addon is Folia-safe.

### Paper and Purpur 1.21.11 compatibility

4.1.35 also adds an explicit compatibility lane for Minecraft 1.21.11:

- Slimefun source is compiled against the **Paper 1.21.11 API** as a compatibility gate.
- The normal production 4.1.35 JAR is boot-tested twice on both Paper 1.21.11 and Purpur 1.21.11.
- Both 1.21.11 runtime checks use Java 21.
- `/sf versions` avoids the newer Adventure `TextComponent.Builder.build()` binary descriptor so the same production JAR works across the 1.21.11 and 26.2 Paper-family Adventure runtimes.

**Paper 26.2 / Minecraft 26.2 on Java 25 remains the primary supported production line.** The 1.21.11 lane exists to preserve a validated compatibility option for servers that intentionally remain on that release.

### Curiosities are opt-in by default

Adventurer's Curios in `configSFLAddons.yml` now stays **disabled by default** unless the server owner explicitly enables it.

- Fresh installs keep `enabled: false`.
- Existing servers with `configSFLAddons.yml` already set to `enabled: true` remain enabled.
- An older explicit legacy Curiosities toggle is migrated using its existing value.
- Merely upgrading an existing Slimefun installation no longer turns Curiosities on automatically.

This keeps Slimefun Legacy additions discretionary and prevents servers from receiving extra gameplay content just because they upgraded the core.

### Resonance Beacon effect-state recovery

Existing Resonance Beacons that already have enabled powers but are missing the newer player-progression entries now recover their configured gameplay effects instead of showing a powered beam and area with every power resolving to Tier 0.

- Already-configured native powers recover a missing progression entry at **Tier I**.
- Existing Activator **3x3** and **5x5** modes preserve their matching **Tier II** and **Tier III** recovery level.
- Existing higher paid/unlocked tiers are never reduced or overwritten.
- Imported legacy `BeaconData` records keep their explicit imported power tiers and can recover their fixed compatibility owner if the owner key is absent.
- Powers that were not already configured are **never unlocked automatically**.

This recovery is persisted, so affected existing beacons should resume applying player and area effects after upgrading and performing a full server restart without needing to be broken, replaced, or repurchased.

### Resonance Beacon pulse reliability

The Resonance Beacon gameplay pulse no longer depends on a coordinate-shifted `gameTime % 20` phase. Slimefun block tickers normally run every 10 ticks, so some beacon coordinates could repeatedly miss that phase forever: the pyramid, enabled-power GUI, effective area preview, and yellow beam could all look correct while Strength, Speed, Flying, crops, furnaces, spawners, and every other periodic effect never executed.

4.1.35 now uses an independent elapsed-game-time throttle per beacon. The first valid ticker invocation can apply immediately, then each beacon is limited to at most one gameplay/energy pulse every 20 game ticks. Electric operation uses that same pulse; turning electric mode on only adds the configured energy requirement and no longer changes the scheduling semantics.

### Core storage and chunk lifecycle improvements

4.1.35 reduces unnecessary retention of Bukkit world, chunk, and location objects in the storage runtime. Delayed writes and unloaded chunk caches now use safer immutable identity data and release normal block-storage caches only after pending reads, writes, inventories, and ticker state are safe to detach.

These changes are intended to reduce long-running memory retention while preserving existing database rows, storage keys, saved-world data, and normal Slimefun machine behavior.

### Safer scheduler and runtime behavior

Chunk-related work is routed through ownership-safe scheduling paths without resolving Bukkit blocks before scheduler handoff. This improves compatibility with modern Paper scheduling rules and continues the groundwork for experimental Folia support without changing normal Paper Cargo or Energy semantics.

### Startup and item-model reliability

Item-model defaults are loaded before immutable Slimefun item templates are created. This fixes startup finalization regressions that could interfere with normal PostSetup processing, Curios, Adventurer's Tools, Irradiated Arsenal, world settings, and item loading.

Paxel model handling and enchant compatibility were also refined so the newer Deepcore and Curios tools remain visually independent and behave more consistently with their underlying pickaxe/shovel tool roles.

## Compatibility

- **Paper 26.2 / Minecraft 26.2** — primary supported line, Java 25, two-boot runtime tested
- **Purpur based on Paper 26.2** — supported, Java 25, two-boot runtime tested
- **Folia based on Paper 26.2** — experimental, Java 25, two-boot runtime tested
- **Paper 1.21.11** — supported compatibility line, Java 21, API-compile and two-boot runtime tested
- **Purpur 1.21.11** — supported compatibility line, Java 21, two-boot runtime tested
- Slimefun-owned classes continue targeting **Java 21 bytecode**

Addon compatibility still depends on each addon's own Minecraft/Paper version support. Folia additionally requires every installed addon to be region-thread safe.

## For server owners

4.1.35 is intended as a drop-in upgrade for existing Slimefun Legacy installations. Back up your worlds, Slimefun data, databases, and addon data before changing core versions, and perform a full server restart rather than `/reload`.

This release continues the Slimefun Legacy goal of preserving the classic Slimefun experience and addon API while keeping the core usable across modern Paper-based servers.
