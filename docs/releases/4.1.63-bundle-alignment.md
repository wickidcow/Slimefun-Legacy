# Matching core and addon release inputs

The master-push full-stack workflow formerly fell through to the latest published release ZIP while building the new core. That could test an old addon set instead of the exact candidate. PR selection already used the candidate artifact and remains unchanged.

The downloader now accepts an explicit push event as well as its default pull-request event. It requires the same workflow path, full head SHA, event and verified source manifest. A missing/failed newer run does not fall back to an older successful run, a different event or a previously published ZIP. The master-push workflow uses its own GITHUB_SHA for both requested head and source.

The full-stack core build also records the actual checkout source/time, disables build/configuration caches and runs its artifact metadata/packaging check before upload. No production Java, item identity, data format or addon source selection changes. Version4.1.63 and manifest revision100 are unchanged.
