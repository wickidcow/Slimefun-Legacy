# Slimefun Legacy 4.1.67

This maintenance release keeps one storage lock registered until every caller holding or waiting for it has finished. It retains all 45 revision-107 addon selections, including HotbarPets 1.0.3 and SimpleMaterialGenerators 1.0.5. The previous published stable regression baseline is 4.1.66 at `22ae22c4e32fd3b086565922f4427206d0f4b065`.

## Scoped storage safety

An unlocked lock can still have callers that already obtained its reference. The previous cleanup could remove that registration, allowing a later caller to create a second lock for the same scope. Controlled tests reproduced simultaneous entry into a supposedly exclusive storage section.

The corrected helper reserves each acquisition before waiting and retires its entry only after all held and waiting acquisitions have released it. Blocking acquisition stays outside the atomic map callback, so unrelated hash-colliding scopes can still progress. Reentrancy, default non-fair locking, interrupt-status behavior, wrong-owner exceptions and missing-unlock behavior are preserved. Unused scope entries are reclaimed rather than kept forever.

## Existing items and addons

No item/research IDs, saved field names or types, inventory codecs, database schemas, block/backpack/storage identities, recipes, menus, capacities, machine rates, transfer priorities, save cadence or migration defaults change. No migration or data rewrite is required or enabled. The lock fix cannot reconstruct data lost before installation.

The complete 45-addon revision-107 source selection is retained unchanged and rebuilt against the exact versioned core. Existing standalone addon versions are preserved. The core is supplied as a raw drop-in JAR; SF_Addons_1.21.11-26.3.zip is the aggregate addon bundle. This release does not replace old core release assets or tags.

## Validation scope

The correction includes twelve permanent real-thread regression scenarios, deterministic original-binary failure controls, reentrant contention, unrelated equal-hash scopes, 16,000 protected updates and cleanup of 4,000 completed scopes. The versioned source must independently pass core/API/platform checks, the full maintained compiler, its matching 45-addon build and restart checks, plus byte-identical clean-build publication checks. Earlier development results are not relabeled as final release results.

These tests do not certify every populated customer world, live-client interaction, database deployment, crash, external addon concurrency, Folia region interaction, future API or cross-fork rollback. The reproduced issue is a helper-level race, not a diagnosis that a particular customer's world was damaged. Scope keys must remain stable while acquired, and hasLock remains a registry snapshot rather than an atomic maintenance barrier. No measured TPS improvement is claimed.

Minecraft 1.21.11 is the runtime floor, not an age cutoff for saved items. Paper 26.3 is the primary target, with Paper/Purpur prioritized and derivative-server safety qualified. Java 21 plugin bytecode is retained while current builds use Java 25.

## Installation

Stop the server normally and back up worlds, player data, plugin directories and databases. Test the matching core and intended addon JARs on a disposable copy first. Replace existing JARs without leaving duplicate versions, and do not use live reload. Keep existing registrations and migration settings unless deliberately changing them. Review startup logs and /sf doctor before optional repairs; unreadable records are recovery tasks, not empty inventories to overwrite.
