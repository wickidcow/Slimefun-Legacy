# Slimefun Legacy 4.1.45 — Automation & Energy Performance

Slimefun Legacy 4.1.45 is a focused performance and maintenance release based on live AlbionMC profiling. It trims repeated work from two of the next most visible hot paths while keeping established machine behavior, addon integrations, item metadata, and saved-world compatibility intact. This build also includes a targeted multiblock compatibility fix for addon machines that contain smaller legacy multiblock patterns inside their structure.

## 🩺 IE1 → IE2 Doctor migration hotfix

- Added `/sf doctor ie2 status|scan|migrate|refresh` as a safe convenience bridge to the installed InfinityExpansion2 Doctor.
- IE2 also registers its migration engine with Slimefun Legacy's addon-doctor API, so `/sf doctor addons scan` can report IE1 migration work and `/sf doctor addons repair confirm` can perform the loaded-scope migration.
- The same IE2 migration engine handles both placed IE1 Slimefun machine/block records and IE1 item stacks; Slimefun does not maintain a duplicate mapping table.
- Migration remains bounded to loaded chunks, inventories/entities and online players. Unloaded chunks are handled when they load rather than being force-loaded during a doctor pass.
- The bridge has no hard InfinityExpansion2 compile dependency; `/sf doctor ie2` simply reports that IE2 is unavailable when the addon is not installed.

## ⚙️ Enhanced Auto Crafter

- Reuses the custom crafter interactor resolved for the current ticker pass instead of repeatedly reading the same block storage.
- Reuses stable per-pass machine values such as location and energy cost where safe.
- Keeps the defensive energy re-check after addon callbacks before committing a craft.
- Leaves existing recipe predicates, virtual-item handling, output-fit checks, and full `ItemStack` output cloning unchanged.
- Adds a null guard when resetting custom crafter integration state after block removal.

## ⚡ Energy Regulator / EnergyNet

- Avoids repeatedly walking connector/player-head presentation state while the network transport state has not changed.
- Topology and powered-state changes still refresh immediately.
- Adds staggered periodic revalidation so external or vanilla state changes are reconciled without forcing every loaded regulator to perform the same connector walk every cycle.
- Actual energy discovery, routing, transfer, capacity, and stored-energy semantics remain unchanged.

## 🧱 Multiblock compatibility

- Improved overlapping multiblock handling so less-specific nested structures no longer activate alongside the intended larger machine.
- When multiple structures match the same interaction, the match with the most required blocks takes priority.
- Equal-specificity matches keep the existing reverse-registration fallback behavior for machines that intentionally share a layout.
- Fixes FN Amplifications machines also activating the legacy Slimefun Grind Stone because their fence-over-dispenser core matched the smaller Grind Stone pattern.
- Normal standalone Grind Stone behavior remains unchanged.

## 🧩 Compatibility and safety

- Paper 26.2 remains the primary supported platform.
- Purpur 26.2 is supported.
- Folia 26.2 remains experimental.
- Paper/Purpur 1.21.11 compatibility remains covered by the release gates.
- Built with Java 25 and verified to a Java 21 bytecode target.
- Existing addon-facing Slimefun APIs, item IDs, storage formats, and saved-world data are unchanged by this performance and compatibility pass.

## 📦 Addons & dependencies bundle

This release also includes `SFL_AddonsNDependencies.zip`, the current Slimefun Legacy addon/dependency bundle.

The ZIP is provided as a convenient tested starting set for Slimefun Legacy servers. It is **not required to run the Slimefun core**, and server owners should still review the included addons, keep only the ones they actually use, and back up their server before replacing plugin files.

## Release assets

- `Slimefun-Legacy4.1.45.jar`
- `SFL_AddonsNDependencies.zip` — be sure to check for newer addon/plugin updates before deploying.

> This release remains focused on measured maintenance and safe compatibility fixes, with larger recipe-matcher or inventory-indexing changes deferred until they can be proven safe for custom items and third-party addon behavior.
