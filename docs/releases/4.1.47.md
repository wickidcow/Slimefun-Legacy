# Slimefun Legacy 4.1.47

## Doctor migrations, ticker efficiency and compatibility hardening

Slimefun Legacy 4.1.47 packages the core work completed after the final 4.1.46 release. The release adds a guarded addon-owned legacy item migration path, reduces idle ticker/profiler overhead, and expands release compatibility coverage across the maintained addon ecosystem while preserving the existing storage schema, item IDs, Cargo/Energy behavior and public compatibility boundaries.

## Legacy item migration diagnostics

- Added a registry for explicit legacy Slimefun item-ID mappings.
- Added `/sf doctor migrations status`, `list`, `unknown`, `plan` and `providers` diagnostics.
- Migration planning remains conservative: unknown IDs without a declared replacement are reported instead of guessed.
- Core dry-run planning does not rewrite addon persistence, block storage, Cargo data or Energy data.
- Added an addon-facing `LegacyItemMigrationProvider` API so each addon can own the persistence-specific migration logic for its own data.

## Guarded provider execution

- `/sf doctor migrations scan <plugin>` runs the provider in read-only mode and only prepares an execution plan when mapping validation and the provider scan are clean.
- Clean scans create a short-lived execution fingerprint; prepared plans expire after 10 minutes.
- `/sf doctor migrations execute <plugin> <fingerprint>` requires the matching prepared fingerprint before the provider repair path can run.
- Missing targets, unsafe mappings, provider failures, expired plans and incorrect fingerprints fail closed.
- A fresh scan is required when a plan expires or becomes invalid.
- Operators are explicitly instructed to make an offline backup before executing a provider-owned migration.

## Ticker and profiler efficiency

- Changed ticker profiling to be request-driven with sparse background telemetry instead of paying full profiler cost continuously.
- Added idle fast paths that skip failure-cleanup work when no ticker failures are active.
- Skips circuit-breaker probing when no circuits are open.
- Skips targeted-pause lookups when no targeted pauses exist.
- Reuses ticker-registration snapshots until registrations actually change instead of rebuilding the same snapshot every cycle.
- Clears cached runtime state when ticker registrations are removed and drops empty chunk state after cleanup.
- These changes preserve normal machine tick behavior while reducing bookkeeping overhead on healthy servers.

## Addon compatibility release gates

- Expanded compatibility CI so maintained `wickidcow` Slimefun addon forks receive individual baseline-vs-candidate source-build and binary-linkage coverage.
- Keeps the four required Legacy forks release-blocking while additional maintained forks and representative upstream/Gugu projects remain advisory.
- Added aggregate classification auditing for `PASS`, `BASELINE_BUILD_FAILED`, `LEGACY_COMPATIBILITY_FAILED` and `INSTRUMENTATION_ERROR` results.
- CI-only fork coverage can be broader than `/sf versions`; runtime addon recognition remains intentionally curated and does not claim exact-build compatibility merely because a repository is tested in CI.
- Explicitly excludes repositories that are not valid standalone addon targets, including the RykenSlimeCustomizer content-pack repository and retired WorldTaste coverage.
- Added narrowly scoped support for the historical `com.github.StarWishsama:Slimefun4` Maven coordinate used by Gugu SlimeCustomizer.
- The Gugu SlimeCustomizer baseline/candidate comparison now runs successfully without broad StarWishsama dependency rewriting.

## Release baseline

- 4.1.47 compares against the exact released Slimefun Legacy 4.1.46 tag commit `062f9480d156873a7240d827246d67c2dfd3316f` as the release-blocking previous-stable baseline.
- The historical 4.1.15 compatibility floor remains advisory for long-term drift visibility.
- Required addons that build against 4.1.46 but regress against 4.1.47 continue to block release.

## Platform compatibility

- Paper 26.2 remains the primary supported platform.
- Purpur 26.2 remains supported.
- Folia 26.2 remains experimental and still requires Folia-safe addons.
- Paper/Purpur 1.21.11 compatibility remains covered by dedicated compile/runtime smoke gates.
- Built with Java 25 and verified to the existing Java 21 bytecode target.

## Release assets

- `Slimefun-Legacy4.1.47.jar`
- `SFL_AddonsNDependencies.zip`

The reproducible-release workflow builds the exact release source twice and requires byte-for-byte equality before publishing. A new 4.1.47 release inherits the validated 4.1.46 addon bundle unless a 4.1.47 bundle has already been published and validated.
