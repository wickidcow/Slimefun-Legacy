# Slimefun Legacy 4.1.68

This maintenance release protects saved inventory records from changes made through exported byte arrays. It includes the merged RecordSet correction and uses the published 4.1.67 source, `5cb1e47c35a2b85ccc342dbf4121fac4bf9a1969`, as its required compatibility baseline.

## Saved inventory protection

A read-only record previously exposed its internal binary buffers. Code reading a record could accidentally change those buffers before a queued database writer saved them. The corrected accessors return copies owned by the caller, so editing an exported array cannot modify the stored record or another caller's view.

The map returned by `getAllValues()` remains live and structurally read-only. It retains each exported array's identity until the corresponding source value is replaced, preserving normal map behavior. Text and key-only lookups avoid copying item buffers. The core production change is confined to RecordSet; serialization readers and writers, database schemas, saved field names and types, item/research IDs, backpack identities, recipes, capacities, machine rates, transfer priorities and migration defaults remain compatible.

No migration or item conversion is required. This prevents the reproduced buffer-ownership error; it does not reconstruct records damaged before installation or make concurrent record writes supported.

## Addon bundle

The matching `SF_Addons_1.21.11-26.3.zip` is bundle revision 109 and contains the 45 maintained addons. It includes MagicExpansion 1.1.8 and DankTech2 1.1.03.

DankTech2 preserves pack IDs, filters, counts and unknown typed metadata during upgrades, makes admin replacement safe when delivery fails, and prevents stale menus or upgrades from restoring a retired pack ID. Its registry uses a readable native item representation and recognizes the known historical Slimefun item alias. Other unreadable item records stop addon startup with the original registry file intact. Alias recovery requires a retained item payload; it cannot recreate data already removed by an older save. The addon includes 54 passing regressions and a reusable native Paper probe for operations, restart, alias recovery and safe startup refusal.

Each source selection must pass the current core's build and runtime gates before publication. The canonical manifest records its bundle revision and exact core/addon source commits. The raw core JAR and matching addon ZIP are published together under the new version; existing core release tags and JARs are retained.

## Verification

The RecordSet correction includes 51 permanent regressions covering binary exports, map behavior, actual SQLite adapter writes and reads after reopening the database, and item metadata preservation. Restoring the original RecordSet implementation reproduced 46 assertion failures in the same focused suite. Those prior results establish the defect; the versioned release independently requires the full core suite, API and platform checks, the canonical 45-addon build, matching restart checks and two byte-identical clean release builds.

Minecraft 1.21.11 remains the minimum runtime version, with Java 21 plugin bytecode and Paper 26.3 as the primary target. Paper and Purpur are prioritized. Folia remains experimental: startup and controlled fixtures do not establish every addon's region safety. Generated fixtures do not certify every historical player world, arbitrary concurrency, database deployment, crash or cross-fork rollback. No measured TPS improvement is claimed.

## Installation

Stop the server normally, preserve your existing worlds and plugin data, and replace the old core and intended addon JARs without leaving duplicate versions. Use a full restart. Existing items, pack identities and migration settings remain in place. Check startup logs and `/sf doctor`; an unreadable record should remain available for recovery rather than being treated as an empty inventory.
