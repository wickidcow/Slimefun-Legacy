# Slimefun Legacy 4.1.48

## Performance, safe updating and Enhanced Guide 4.2

Slimefun Legacy 4.1.48 continues the 4.1.47 stability line with a focused performance pass, restart-safe update staging, Enhanced Guide 4.2 recipe-usage browsing, and additional compatibility and release-integrity hardening. Paper 26.2 remains the production baseline; Paper 26.3 work remains a separate advisory pre-release lane.

## Ticker and EnergyNet performance

- Reduced normal ticker hot-path allocation and cleanup overhead without changing machine cadence or callback ordering.
- Reused registered ticker block positions instead of rebuilding equivalent coordinate wrappers during dispatch.
- Kept detailed `/sf tick` samples request-driven while making passive telemetry aggregate-only.
- Reduced idle EnergyNet profiler bookkeeping and callback allocation when no profiler sample is active.
- Preserved generator timing accounting and reliable profiler closure across early-exit paths.

## Safe update manager

- Added `/sf update` and `/sf update check` for operator-visible Slimefun Legacy update discovery.
- Added `/sf update install` to validate and stage newer Slimefun Legacy and installed maintained-addon JARs for the next normal restart.
- Update discovery uses the latest stable `wickidcow/Slimefun-Legacy` GitHub Release and its tested addon bundle.
- The updater validates the entire selected update set before staging the first JAR so a missing or mismatched asset cannot leave a partially staged set.
- Plugins are never hot-reloaded; a normal restart is still required.

## Enhanced Guide 4.2

- Added **Recipes Using This Item** reverse-recipe browsing for ordinary Slimefun recipes and supported machine/provider recipes.
- Reverse indexing begins only after explicit player use, yields across ticks, and caches the completed per-world index instead of scanning during ordinary guide rendering.
- Added configurable per-tick and elapsed-work budgets for reverse indexing.
- Added consistent Enhanced Guide controls across category, bookmark and search pages:
  - left-click keeps the normal action;
  - right-click gives a full stack in cheat mode;
  - shift-click toggles bookmarks and takes priority over right-click.
- Hardened addon recipe discovery so missing optional classes referenced by public addon signatures fail closed instead of aborting the recipe-usage index.
- Hardened mapped addon recipe normalization so non-null keys that cannot be converted into actual item inputs are not published as fake zero-input recipes.

## Settings, links and branding

- Refreshed the Settings & Info page to identify the build as **Slimefun Legacy by wickidcow/TanukiTomo**.
- The Wiki button now points to the Slimefun Legacy GitHub Wiki.
- The Addons button now points to the Slimefun Legacy releases/addon bundle location.
- Existing built-in and addon-injected settings remain unchanged.

## Release artifact integrity

- Expanded release verification to require concrete production runtime classes from Slimefun, Dough and bStats inside every distributable Shadow JAR.
- Release reports now include required-runtime-class coverage in addition to source identity, Java bytecode target, dependency packaging and previous-stable baseline checks.
- The reproducible-release workflow still builds the exact release source twice and requires byte-for-byte equality before publishing the official JAR.

## Compatibility and release baseline

- 4.1.48 compares against the exact released Slimefun Legacy 4.1.47 source commit `eeecbb5dc104570f2131d287e80f281cd1bfd7a8` as the release-blocking previous-stable baseline.
- The historical 4.1.15 floor remains advisory for long-term drift visibility.
- Required addons that work against 4.1.47 but regress against 4.1.48 continue to block release.
- Maintained addon forks and representative upstream/Gugu projects remain covered by source-build and binary-linkage checks according to their configured tier.

## Platform support

- Paper 26.2 / Minecraft 26.2 remains the primary supported platform.
- Purpur based on Paper 26.2 remains supported.
- Folia based on Paper 26.2 remains experimental and still requires Folia-safe addons.
- Paper/Purpur 1.21.11 compatibility remains covered by dedicated compile/runtime smoke gates.
- Built with Java 25 while retaining the Java 21 bytecode target for Slimefun-owned classes.
- Paper 26.3 remains a parallel pre-release compatibility track and is not promoted to the production baseline by this release.

## Release assets

- `Slimefun-Legacy4.1.48.jar`
- `SFL_AddonsNDependencies.zip`

The 4.1.48 reproducible-release workflow preserves an already-published 4.1.48 addon bundle when refreshing the release. When creating 4.1.48 for the first time, it falls back only to the validated current 4.1.47 bundle (`sha256:318f5c846416090041ba7d0f20dfa4696928f6061af0c45e1c9b07e8bd0c998e`) so the release cannot silently roll the maintained addon collection backward.
