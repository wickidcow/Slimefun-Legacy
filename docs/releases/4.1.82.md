# Slimefun Legacy 4.1.82 — Historical item recovery and coordinated 45-addon package

This is the distinct new **v4.1.82 release candidate**. Publish only after a reviewed exact-source build, the canonical r157 addon ZIP and all required reproducible/native/runtime gates pass. Existing v4.1.81 and older releases remain immutable.

## Core and data compatibility

- **Slimefun Doctor:** opt-in, bounded historical item compatibility diagnostics and recovery, with explicit preview, backup, readback validation and guarded rollback. Do not silently replace Slimefun items in player inventories or stored containers.
- **Historical inventories are not rewritten automatically.** Server-owned chest, Cargo, QuickShop and old-world production upgrades remain **UNTESTED** until independently staged; the core item probe is not a promise of universal real-time player/world migration.
- **Crafting restrictions:** preserve the existing `CraftingRestrictions.yml` administrative disable/enable policy and item identities across upgrades.
- **Guide interoperability:** addon Piglin Talisman and Ender Piglin Talisman may register inside the original Slimefun talisman and ender-talisman categories without weakening unrelated addon item-group ownership controls.
- **Build compatibility:** Maven's fully qualified install-plugin goal reduces plugin-prefix ambiguity, but transient dependency-network failures may still require a targeted CI retry. Other tested core/API changes from the verified Doctor PR are retained.

## Platform and support boundaries

- **Primary:** Paper 26.3, with Paper/Purpur runtime and addon evidence.
- **Also supported/tested:** Paper 26.2 and the 1.21.11 baseline.
- **Experimental:** Purpur 26.3, Folia 26.3 and Leaf require their own test evidence; not all 45 addons are Folia region-safe. Networks, IE2 and InfernalExpansion have no asserted Folia runtime admission.
- **Advisory only:** Minecraft 26.1.2 source compilation is not runtime or rollback certification.
- Java 21-compatible distributable plugin bytecode and Java 25 build/current-runtime tooling are checked separately.

## Required release integrity and four assets

The release workflow requires two clean reproducible core builds, exact-source 45-addon bundle verification, official binary bytes/receipts and native/full-stack runtime evidence for the actual release commit. The published asset checksums must be measured against the final files, not copied from a PR preview.

1. `Slimefun-Legacy4.1.82.jar` — exact-source Java core plugin.
2. `SF_Addons_1.21.11-26.3.zip` — canonical 45-addon r157 ZIP, manifest and checksum evidence.
3. `SlimefunLegacyRP.zip` — separately verified Java-player resource pack.
4. `SlimefunLegacyRP_Geyser.zip` — optional, unchanged separately pinned Geyser server drop-in (not generated or merged with the Java pack).

**Upgrade guidance:** Shut down the server, back up worlds, inventories, plugin configuration and Slimefun/addon storage databases, then upgrade the core and its selected addon JARs together. Avoid `/reload`. Run Doctor scans before any optional confirmed repair, retain backup/rollback receipts, and do not infer that live shops or legacy containers were automatically migrated.
