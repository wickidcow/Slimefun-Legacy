# GuGu indexed universal block lookup — bounded, verified Legacy adaptation

**Upstream source:** SlimefunGuguProject/Slimefun4 commit `2f2a286a9fab2bb7297f2af321630aa3aa429564` introduces BlockPosition-to-UUID universal block location indexing. Legacy's 4.1.78 source `BlockDataController.getUniversalBlockDataFromCache(Location)` still scans all universal data on a lookup, including each stored block's Location conversion, potentially impacting heavy factories and explosion-related access.

**Difference from a direct cherry-pick:** `UniversalBlockLocationHints` caches only a bounded in-memory `location-string -> UUID` candidate. A cache hit must revalidate `isDataLoaded`, `lastPresent` and the original exact `Location.equals` against the live `loadedUniversalData` map before it can return anything. An invalid/stale hint is removed atomically and the original full scan remains the fallback. Cold or old-world data works as before; a null-world query uses the original scan. No disk serialization, block identities, public Java symbols, ticker frequencies or menus change.

**Lifecycle:** indexing on successful newly created block, post-hydration inventory load (AFTER recovery/inventory/ticker success), and successful move; invalidate on block removal and failed inventory hydration; clear hints after storage shutdown. A bounded cache prevents unlimited stale keys if machines move repeatedly. When full it evicts a single advisory hint instead of clearing all 65,536 hints, reducing sudden cold-scan bursts; the fallback remains the original authoritative scan. Concurrent warmups are capacity-locked while reads remain lock-free. If another region concurrently replaces a hint, identity-sensitive eviction never erases the new UUID. Cache misses may still be linear and no performance benchmark is claimed.

**Tests:** unit checks for hit acceleration, missing/unloaded records, replacement after migration, cross-world coordinates, identity-sensitive deletion and bounded capacity. Additional native old-world inventory recovery, failed decoding, migration-restart and Folia multi-region acceptance is required before claiming performance benefits or new release readiness.

**Risk/rollout:** this is a Java-only, nonpersistent acceleration. Slimefun 4.1.78 JAR, 44-addon ZIP and all external plugin artifacts remain unchanged. Keep PR draft until the exact-head API, storage, 1.21.11 / 26.2 / 26.3 runtime and addon compatibility suites pass; capture comparable profiler data before concluding a speedup. Never include this in a release based solely on a green unit build.
